# Critical review, 2026-09-27

Four independent reviewers challenged the template from different angles: a skeptical staff engineer
(complexity and DX), a state-of-the-art researcher (late-2026 practice for AI-assisted development), a
prospective adopter (starting a real B2B product), and a devil's-advocate architect. They read the repository
at `f256b42` and cited sources. This file keeps their conclusions and what we decided to do about them.

## Where they agreed the template is strong

- The contract idea works in practice: an agent simulation implemented a feature from `AGENTS.md` alone, and
  the gates caught forgotten codegen, a forgotten migration and a UI-to-server import.
- Security posture (CSRF, strict CSP, narrowed Better Auth surface, atomic rate limits) and `docs/operations.md`.
- `pnpm ci:local` makes every claim reproducible without GitHub.
- The HttpApi contract with database-free handler tests is the product; nobody recommended replacing it with
  Hono, oRPC, tRPC or server functions.

## Findings we act on without further decisions

Adoption and DX:
- No path to rename the app or remove the example: "proofstack" appears 137 times in about 60 files, and the
  security tests use the posts endpoint as their only authenticated subject. Add `pnpm template:rename`, a
  generic authenticated probe endpoint for the security tests, a documented and CI-checked "remove the
  example" step, and `docs/adopting.md`.
- No way for forks to take template updates: tag releases, keep a CHANGELOG with upgrade notes, document
  merging from a `template` remote.
- First deploy traps: the first account needs a full checkout pointed at production (ship a bundled
  `create-user`), and migrations use a session advisory lock and session `SET`, which break behind PgBouncer in
  transaction mode (Neon, Supabase): use `pg_advisory_xact_lock` and `SET LOCAL`, and support a
  `MIGRATION_DATABASE_URL` for a direct connection. Add deploy recipes (VPS with compose, Fly, Kubernetes) and a
  backups section.
- Portability: `spawnSync('pnpm')` without a shell fails on Windows; the edge uses host networking, which is
  Linux only; the memory-cap advice in `AGENTS.md` is Linux specific.
- `AGENTS.md` is 27 KB (Claude Code recommends under 200 lines; Codex stops at 32 KiB of instructions in
  total): keep a short root file, move the test manual to `tests/AGENTS.md`, turn the workflows into project
  skills, and guard the size in `pnpm check`.
- Open-source readiness: CONTRIBUTING, SECURITY.md, CODE_OF_CONDUCT, issue and PR templates.

AI-assisted development:
- Enforce in configuration what `AGENTS.md` only asks for: `.claude/settings.json` with a `PostToolUse` hook that
  formats and lints the edited file, deny rules for generated files, and allow rules for the common gates.
- A repeatable agent eval (tasks, a runner in a throwaway worktree, graded by the gates and hidden tests), so
  changes to `AGENTS.md` and skills are measured.
- Contract fuzzing with Schemathesis against the running app (the promise is that spec and server agree;
  examples alone don't prove it), plus examples in the OpenAPI document.
- OpenTelemetry through Effect's OTLP exporters, with trace ids in every log line.
- A `REVIEW.md` for AI reviewers. (A Copilot `copilot-setup-steps.yml` was added and then removed: the owner does not
  support Copilot; it reads `AGENTS.md` and `.agents/` on its own.)

Architecture:
- A transaction helper on `Database` before the next feature needs one.
- The SSR in-process client only forwards the cookie and bypasses CSRF and body limits: restrict it to GET and
  read the session once per request.
- Auth failures are open strings with a default branch; make them a closed union with an exhaustive check, like
  API errors. Record the three-surface rule (HttpApi, server functions, Better Auth) in an ADR.
- Postgres 18 `uuidv7()` for new ids while there is no production data.
- `rate_limit` as an UNLOGGED table keyed by `key`.
- Declarative cache invalidation instead of hand-written invalidation per mutation.
- Evaluate progressive-enhancement auth forms (server function `.url` as the form action) and running the
  production server under Node's permission model; record both as ADRs.

## Findings we keep as they are, with reasons

- **Pre-release stack (Effect 4 RC, Nitro beta, Hey API snapshot, TS 7, Node 26).** A decision of the owner;
  the churn is confined to few files and every upgrade is gated. The README states the status.
- **Lighthouse performance gate on PRs.** The owner's requirement (100 with an isolated 99 tolerated). The gate
  already reports "inconclusive" on slow machines; the first real CI run decides whether it needs a different
  cadence.
- **Blocking complexity and duplication gates.** They report zero findings after refactoring, and weakening
  them would invite the god-functions they exist to stop.
- **Not following TanStack's advice to call services directly from SSR loaders**, not adopting Better Auth's
  `cookieCache`, not exposing Better Auth's OpenAPI spec in the contract, no client-side Effect, no Drizzle 1.0
  RC, no llms.txt, no Spec Kit, no third-party docs MCP servers.

## Owner decisions (2026-09-27)

- Product building blocks shipped in the template: the small ones only (development seed, robots.txt,
  sitemap and Open Graph image, light/dark theme toggle, HTML email templates). Durable jobs, organizations,
  roles, OAuth and file uploads are documented in the adopter guide instead.
- Dependency automation: Renovate replaces Dependabot, covering npm, Docker image digests and Actions.
- Forms: TanStack Form with Effect Schema through Standard Schema, with per-field errors from the API's
  `ValidationError`.
- Distribution: a GitHub template repository with `pnpm template:rename`, tagged releases and a CHANGELOG with
  upgrade notes. No scaffolding CLI.
- Clean code for agents (docs/clean-code-audit.md): enforce the audit's rules with Oxlint even where they start
  with many findings, since this is the foundation new projects copy. Components get more room than the audit
  proposed: `max-lines-per-function` 80 in `.tsx` (the audit said 40), 20 elsewhere. The rules land after the
  tooling de-customization, so scripts that are about to be deleted are not refactored first.
